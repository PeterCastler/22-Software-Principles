# Source note: Yagni

- Author: Martin Fowler
- URL: https://martinfowler.com/bliki/Yagni.html
- Accessed: 2026-07-15
- Type: authoritative synthesis of the Extreme Programming practice

YAGNI says not to implement a presumed future capability before it is needed. Fowler identifies costs beyond initial construction: delayed present value, ongoing carrying complexity, and repair when an early guess proves wrong. The rule applies to speculative capabilities and extensibility, not to refactoring, tests, or delivery practices that keep code easy to change.

A low-cost decision that does not add present complexity can still be sensible. The target is the extra complexity carried for a future consumer, not foresight itself.
